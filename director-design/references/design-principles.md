# 9 维度设计原则 — director-design 的 audit checklist 详细 rubric

每个维度 1-5 分。aggregate = 9 维度 / 应用维度数（n/a 不计）。

---

## 1. 信息层级（Hierarchy）

**判断**：用户第一眼是否清楚知道这是什么 / 要做什么 / 主操作在哪。

| 分数 | 锚点 |
|---|---|
| **5/5** | 主标题 + 主操作 + 二级信息层级清晰；视觉权重对应业务权重；F 型 / Z 型扫视路径自然 |
| **3/5** | 主操作能找到但不突出；二级信息有时与主信息混淆 |
| **1/5** | 主操作淹没在装饰中 / 多个元素争夺视觉焦点 / 用户要"找半天"才知道怎么用 |

**判断方法**：mid-squint 测试（眯眼看截图，仍能识别主操作和主信息）。

---

## 2. 布局密度（Density）

**判断**：是否过挤 / 过空 / 对齐混乱 / 卡片滥用。

| 分数 | 锚点 |
|---|---|
| **5/5** | 8/4 像素栅格严格；元素间距遵循 4/8/16/24/32 阶梯；卡片只用于真正需要"独立单元"的内容 |
| **3/5** | 基本对齐但有零散偏差；少数卡片包装了不需要独立的内容 |
| **1/5** | 间距随机；元素挤在一起 / 大块空白无意义；卡片套卡片 / 列表项都包卡片 |

**判断方法**：测量代表性间距，看是否有可识别的栅格 / 阶梯。

---

## 3. 字体系统（Typography）

**判断**：字号 / 行高 / 字重 / 按钮文字是否稳定可读。

| 分数 | 锚点 |
|---|---|
| **5/5** | 字号 ≤ 5 个层级（如 12/14/16/20/24）；行高 1.4-1.6（正文）/ 1.2（标题）；字重 ≤ 3 个（regular/medium/bold）；按钮文字均在 14-16px |
| **3/5** | 字号层级稍多（6-7 个）；行高有零散偏差 |
| **1/5** | 字号层级 ≥ 10 个 / 同一信息层级用不同字号 / 行高过紧（< 1.2）导致难读 |

---

## 4. 色彩与对比（Color & Contrast）

**判断**：是否单色调过重 / 语义色混乱 / 可读性不足。

| 分数 | 锚点 |
|---|---|
| **5/5** | 主色 1-2 个 + 中性色阶 + 语义色（success/warning/danger/info）；正文对比度 ≥ 7:1（AAA）/ 大文字 ≥ 4.5:1 |
| **3/5** | 主色明确；少数文字对比度 4.5-7:1（AA pass，但不够 AAA）|
| **1/5** | 多个主色无主次 / 语义色错用（success 用红）/ 大量文字对比度 < 4.5:1 |

**判断方法**：取代表性文字 + 背景色用 `tinycolor` 等工具算对比度；或对照 WCAG checker。

**注意**：这里只做"视觉判断"层面的对比度初筛；正式 a11y 审查必须 handoff 给 `web-design-guidelines`。

---

## 5. 组件一致性（Component Consistency）

**判断**：按钮 / 输入 / 卡片 / 标签 / 图标是否同一体系。

| 分数 | 锚点 |
|---|---|
| **5/5** | 同类元素视觉完全一致；按钮 ≤ 3 个变体（primary/secondary/ghost）；图标线性 / 填充 / 大小统一 |
| **3/5** | 主要组件一致；少数边缘 case 偏离 |
| **1/5** | 同一页面 3 种风格的按钮 / 输入框 / 图标混用；圆角 / 阴影 / 边框各种乱用 |

---

## 6. 交互状态（Interaction States）

**判断**：normal / hover / focus / disabled / loading / empty / error 是否完整。

| 分数 | 锚点 |
|---|---|
| **5/5** | 所有交互元素 7 状态全覆盖；focus 有键盘可见 outline；loading 有 spinner / skeleton；empty / error 有专门 UI |
| **3/5** | normal / hover / disabled 全；focus 在主要元素有；empty / error 状态用通用文案 |
| **1/5** | 只有 normal；hover 没反馈 / focus 看不见 outline / loading 直接卡死无提示 / empty 是白屏 |

---

## 7. 响应式（Responsive）

**判断**：移动端是否溢出 / 遮挡 / 换行失控。

| 分数 | 锚点 |
|---|---|
| **5/5** | 375 / 768 / 1024 / 1440 4 断点均干净；窄屏元素堆叠合理；图片自适应；触摸目标 ≥ 44×44px |
| **3/5** | 默认尺寸 OK；窄屏有零散溢出但不影响主操作 |
| **1/5** | 移动端横向滚动 / 文字截断 / 按钮重叠 / 弹窗撑出视口 |

**判断方法**：截图 4 断点（参考 flow-project-finish Step 3.4 并行截图）。

---

## 8. 产品气质（Product Tone）

**判断**：是否符合目标场景；工具型产品应克制高效，营销页应明确第一屏信号。

| 分数 | 锚点 |
|---|---|
| **5/5** | 风格匹配产品类型（工具 = 克制 / 营销 = 强信号 / 内容型 = 优雅阅读 / 数据型 = 信息密度）；调性一致 |
| **3/5** | 大方向对；个别元素调性偏移（工具型加了过多营销动画）|
| **1/5** | 工具型用 SaaS 营销页配色 / 营销页第一屏看不出价值主张 / 内容型字号过小不利阅读 |

**产品类型快速识别**：
- **工具型**（VS Code / Notion / Linear）：克制 / 信息密度高 / 少动画
- **营销页**（landing page）：明确首屏 / hero + CTA / 故事叙述
- **内容型**（博客 / Medium）：阅读优先 / 大留白 / 字体讲究
- **数据型**（dashboard / analytics）：信息密度极高 / 表格 / 图表 / 筛选
- **社交型**（推特 / 小红书）：feed 流 / 互动反馈 / emoji 友好

---

## 9. 完成度（Polish）

**判断**：是否有 demo 感 / AI slop / 无意义装饰 / 临时占位。

| 分数 | 锚点 |
|---|---|
| **5/5** | 无 lorem ipsum / 无 "Card 1 / Card 2" 占位文案 / 无浮动渐变球 / 无意义 emoji；所有数据 / 文案像真实产品 |
| **3/5** | 主要区域完成度高；个别次要区域留占位（已标注 "TODO: ..."）|
| **1/5** | 满屏 lorem ipsum / 渐变球到处飞 / 紫色科技感 / 玻璃拟态滥用 / emoji 装饰 / "Premium / Pro / Beta" 标签到处贴 |

**AI slop 高发清单**（强烈警示）：
- 紫色 → 蓝色渐变背景
- 玻璃拟态（backdrop-blur）大面积使用
- 浮动渐变球（mesh gradient blob）
- 莫名其妙的 emoji 装饰
- "Powered by AI" / "Premium" 徽章
- 过度对称布局
- card 套 card 套 card

---

## aggregate 计算

```
aggregate = sum(应用维度分数) / 应用维度数
```

- 9 维度全应用：aggregate = sum / 9
- 部分 n/a（如 audit 纯静态截图，"7. 响应式"无证据）：sum / 实际应用维度数

**verdict 判定**：

**单一真相源**：band 边界与标签以 `SKILL.md`「Aggregate → Verdict 映射」段为准（与 `references/audit-rubric.md` §4.1 的 director-design 列一致）。本文件**不再重列**该表以避免漂移。速记（权威定义见上述两处）：

| aggregate | verdict |
|---|---|
| ≥ 4.5 | `pass` |
| 4.0 - 4.4 | `pass-with-fixes` |
| 3.0 - 3.9 | `needs-redesign` |
| < 3.0 | `blocked` |

**任一维度 ≤ 2/5** → 即使 aggregate 高，verdict 降级为 `needs-redesign`（局部塌方）。详细降级红线见 SKILL.md「本 skill 红线触发」。

## 同分裁决优先级（多个 variants 同分时用）

当 2-3 个 variants 的 aggregate 相同时，按以下"硬规则维度"排序裁决：

1. **信息层级（Hierarchy）** — 用户能不能一眼明白
2. **完成度（Polish）** — 是否有 demo 感 / AI slop
3. **产品气质（Product Tone）** — 是否符合目标场景

排在前面的维度分数高者胜出。原因：这三个维度直接决定"用户能否真正用这个产品"，比布局密度 / 配色 / 字体等可调维度更难后期补救。

例：variant-A aggregate=4.6（信息层级 5/5），variant-B aggregate=4.6（信息层级 4/5）→ 选 A。

---

## 应用约束

- 每次 audit 必须**对照本文件的 1/3/5 锚点**评分，不允许凭直觉给分
- 任何维度 n/a 必须**显式说明**为什么跳过（如"无视觉证据" / "纯后端任务"）
- 新增维度必须**先改本文件**再用，不允许临时编新维度
- 评分时**优先用项目设计系统作为对照**（项目内已有 tokens 是基准），其次外部最佳实践
