# sspai 文案调性

## 总原则

少数派读者偏「数字生活、效率工具、独立开发者」群体。文案默认调性是**克制的好奇 + 实事求是 + 克服自卖自夸**。

## 推荐结构（项目宣传贴）

```
[导言一段 / 50-100 字]
- 一句话说清这是什么 + 谁会用 + 解决什么问题
- 自家项目要在导言或第二段表明作者身份："我自己开发的"

## 为什么做这个 / 起因
- 用户场景下的具体问题，不是泛泛痛点
- 一两段，不超过

## 核心功能 1
- H2 + 一段文字 + 可能的截图
- 不堆 bullet list（少数派排版偏长文）

## 核心功能 2
## 核心功能 3
## 核心功能 4
（功能数量 3-6 个为宜，每个 100-200 字）

## 安装 / 获取
- 商店链接 / GitHub / 官网，控制在 3-5 条
- 跨浏览器 / 跨平台说明
- 没上架的别写有，写「即将支持」

## 路线图（可选）
- 1-3 条用户能感知的项目方向
- 不要写不打算做的虚张声势

## 反馈与支持
- GitHub issues / 邮箱 / 推特
- 如果接受赞助，链接放这里，**不要放显眼位置**
- 一句「欢迎反馈」结尾，不要「求支持 / 求 star / 求 upvote」
```

## 好的开头

✅ 「这是一个我自己开发的浏览器扩展管理器，用来对付装了一堆扩展之后越来越乱的浏览器。」

✅ 「装一年浏览器，扩展从 5 个长到 50 个。每次出问题不知道是哪个搞的——所以我做了 Ext Helper。」

✅ 「介绍一个我业余时间做的小工具：Ext Helper，浏览器扩展的统一管理器。」

## 不好的开头

❌ 「emmm 周末做了个小玩意儿……」（自降身段）

❌ 「这是一款革命性的浏览器扩展管理工具！」（过度营销）

❌ 「家人们谁懂啊，扩展太多崩了！我一怒之下做了……」（互联网黑话）

❌ 「**🚀 Ext Helper 重磅上线！**」（emoji + 加粗 + 营销词）

## 功能描述：好 vs 不好

✅ **好的写法**（具体、可验证）：
> 二分定位是 Ext Helper 的杀手锏。某个扩展把页面搞坏了不知道是哪个？开启 Bisect，每次禁用一半，告诉它「页面好 / 不好」，log₂(n) 步内锁定。32 个扩展最多 5 步。

❌ **不好的写法**（套话、形容词堆砌）：
> Bisect 功能强大、便捷高效，能够帮你**快速、精准**地定位问题扩展，**显著提升**效率。

## 截图配文

每张截图下方用一行文字交代「这张图在展示什么」，不要默认读者看图就懂：

✅ 「卡片视图：扩展按颜色分组，鼠标悬停显示详情」

❌ 「Card View」（光标题没解释）

❌ 「这张图展示了 Ext Helper 的强大功能！」（空话）

## 链接控制

正文里出现的链接限制：

| 链接类型 | 是否必要 | 备注 |
|---|---|---|
| 商店地址 | ✅ 必要 | 主推安装路径 |
| GitHub 仓库 | ✅ 必要 | 透明度 + 反馈渠道 |
| 项目官网 | 可选 | 如果有 landing 页 |
| 文档 | 可选 | 复杂工具才需要 |
| 反馈邮箱 / Twitter | 可选 | 反馈渠道里写一个就够 |
| 赞助 / PayPal | 可选 | 如果加，放反馈段落末尾 |

**不要超过 5 条链接**。链接堆叠会被读者跳过。

## 长度

- 项目宣传贴正文目标 **1500-3500 字**
- 太短（<800）显得敷衍，编辑部不会精选
- 太长（>5000）应考虑拆成系列或改投编辑部走深度长文

## Real-World Reference

成功案例：Ext Helper 首发（2026-05 立即发布）
- 长度：~3500 字
- H2 数量：7
- 内嵌图：3
- 链接：4（Chrome 商店 / GitHub / PayPal / 官网）
- 风格：克制自荐，「我开发的」+ 用户场景 + 功能拆解
