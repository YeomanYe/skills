# 立即发布 vs 投稿编辑部 决策树

少数派后台「发布」环节给两个选项，UI 上是两张并列卡片：

| 选项 | 一句话说清 |
|---|---|
| **立即发布** | 适合短篇、即兴分享、转载分发；发布即公开 |
| **投稿编辑部** | 适合原创深度长文、特约稿件；编辑部审稿，几天到一两周 |

## 决策树

```
文章类型？
├── 自家项目宣传贴（"我做了 X 工具" / 新版本 / 上线）
│   └── ⭐ 立即发布（自家自荐编辑部更挑，常被打回让改成「使用心得」式）
│
├── 自己写的别家产品评测/对比/深度教程（>5000 字、有调研）
│   └── 投稿编辑部（这是编辑部的主菜）
│
├── 数字生活/方法论/思考类长文（个人体悟 + 方法 + 案例）
│   └── 投稿编辑部（精选概率高）
│
├── 转载、汇编、链接合集
│   └── ⭐ 立即发布（编辑部不收转载）
│
├── 短篇即兴分享（< 1500 字）
│   └── 立即发布（太短编辑部不会精选）
│
└── 不确定
    └── 立即发布（事后还有机会被编辑部精选；编辑部审稿等待成本高）
```

## 自家项目宣传贴为什么默认立即发布

1. **编辑部对自荐自家工具会更挑**：他们倾向「独立开发者写自己工具」要拆成「使用心得 / 评测」式，而非纯发布稿
2. **审稿周期长**：几天到一两周，期间不能改不能撤；自家项目 launch 抢的就是「头几天的曝光窗口」
3. **立即发布也能被精选**：UI 文案明确写「优质文章有机会被精选或收录」，立即发布的稿子事后能被编辑部捞起来精选——不是只有走编辑部那条路才行
4. **传播路径**：立即发布后立刻能转到 Twitter / 即刻 / V2EX 拿首批流量；走编辑部的稿子要等编辑部走完审稿流程才能转

## 投稿编辑部什么时候值得走

- 文章是**原创首发**（不是已发过其他平台的转载）
- 内容**够厚**（建议 3500 字以上，最好 5000+）
- **不是自卖自夸**：评测、教程、深度调研、方法论
- 你能**接受 1-2 周的等待**和「编辑部要求改稿」的可能
- 收益是**精选页 / 首页推荐 / 会员专享**——曝光大但延迟也大

## 真实场景示例

| 场景 | 推荐 |
|---|---|
| Ext Helper 1.0 首发宣传贴 | 立即发布 |
| 「我用 Obsidian 三年的工作流」长文 | 投稿编辑部 |
| 「最近发现的 5 个 macOS 小工具」推荐合集 | 立即发布 |
| 「Cursor vs Cline vs Aider 实测对比」深度评测 | 投稿编辑部 |
| 「Ext Helper 是怎么实现 bisect 的」开发笔记 | 立即发布（开发者口吻） |
| Github 仓库 README 改写后转发 | 立即发布 |

## 操作上要做什么

本 skill 默认让用户**自己**点最后那个按钮——agent 不要替按。决策的部分输出建议给用户，让他们当场选。
