# hat 测试用例

> 用于 skill-behavior-test 回归基线。

---

## Case 1: MVP 场景 → 戴 `收`

**Prompt**: "我们要做一个待办清单 MVP,你帮我看看需求列表里哪些必须做。"

**预期**:
- 自动戴 `收` (focus)
- 输出: 最多 3 条致命问题 + 必做 / 可推后 分类
- 末尾告知: `[戴帽:「收」(focus) — MVP 收敛 / 只挑致命]`

**反例**(违规):
- ❌ 给 should-fix 列表
- ❌ 列 > 3 条致命
- ❌ 没末尾告知

---

## Case 2: 风格选型场景 → 戴 `散`

**Prompt**: "帮我想几个 dashboard 配色方案。"

**预期**:
- 自动戴 `散` (explore)
- 输出: 3-5 个实质不同的方案 + 各 trade-off
- 不主动推荐
- 末尾告知: `[戴帽:「散」(explore) — 风格发散 / 给多选]`

**反例**:
- ❌ "我推荐 X"
- ❌ 只给 1 个方案
- ❌ 5 个方案是同一色系微调

---

## Case 3: 上线前走查 → 戴 `严`

**Prompt**: "这个功能下周上线,帮我走查一下。"

**预期**:
- 自动戴 `严` (strict)
- 输出: 已验证 ✓ / 未验证 ✗ + 边界 case + 反例 + 可观测性
- 末尾告知: `[戴帽:「严」(strict) — 上线前走查 / 边角全考虑]`

**反例**:
- ❌ "看起来没问题"
- ❌ 只测 happy path
- ❌ 跳过任何边界

---

## Case 4: 日常小 bug → 默认 `快`

**Prompt**: "utils.ts 第 12 行 null check 漏了,修一下。"

**预期**:
- 默认戴 `快` (lean) — 没特殊信号
- 简短回复,直接给 fix
- 末尾告知: `[戴帽:「快」(lean) — 日常修 / 够用]`

**反例**:
- ❌ 列 8 个 corner case(那是 `严`)
- ❌ 给 3 种修法(那是 `散`)
- ❌ 长篇解释为什么(那是 `教`)

## Case 5: code review → 戴 `挑`

**Prompt**: "帮我 review 这个 PR: https://github.com/foo/bar/pull/42"

**预期**:
- 自动戴 `挑` (critic)
- 输出: must-fix / should-fix / nit 分级 + 漏掉的
- 末尾告知: `[戴帽:「挑」(critic) — code review / 优先挑刺]`

**反例**:
- ❌ "整体不错"(不主动夸)
- ❌ 只挑表面
- ❌ 挑了不给修复路径

## Case 6: 学习新栈 → 戴 `教`

**Prompt**: "我第一次用 Rust,帮我理解一下 ownership。"

**预期**:
- 自动戴 `教` (teach)
- 输出: 做什么 + 为什么 + 类比 + 错误示例 + 下一步
- 末尾告知: `[戴帽:「教」(teach) — 新概念学习 / 每步解释]`

**反例**:
- ❌ 直接贴代码没解释
- ❌ 用 "lifetime / borrow checker" 不解释
- ❌ "你应该已经知道..."

## Case 7: 卡壳求助 → 戴 `问`

**Prompt**: "我不确定下一步该做啥,帮我想想。"

**预期**:
- 自动戴 `问` (ask)
- 输出: 3-5 个澄清问题(目标 / 约束 / 优先级)
- 不直接给答案
- 末尾告知: `[戴帽:「问」(ask) — 卡壳 / 反问引导]`

**反例**:
- ❌ 一来就给答案
- ❌ 问 "你想要什么" 这种空问题
- ❌ 问 > 5 个

## 集成测试场景

### Chain 1: hat + brainstorming

戴 `散` + 调用 `superpowers:brainstorming` → 真正发散的 brainstorm(不是只给 1 方向)

### Chain 2: hat + verification-before-completion

戴 `严` + 调用 `superpowers:verification-before-completion` → 边角全验证(不是只测主流程)

### Chain 3: hat + flow-codex-goal Phase 0

戴 `收` + 跑 `flow-codex-goal` Phase 0 → GOAL.md Scope 段砍掉非必要

### Chain 4: 切帽与主对话状态

任务进行中切帽 → 主对话能识别新 hat 规则 → 输出风格立即变化(不需要重启)

## Case 16: 增强切换 — opt-out 自动切(v3 修订)

**场景**: 任务进行中,当前戴 `快`(严格度 1),用户突然说"这个功能下周上线了"

**预期**:
- detection.md "任务转向信号" 命中"转向到 `严`"(目标严格度 5,+4 增强)
- **opt-out 自动切**:响应**开头第一行**通知:
  ```
  （已自动换戴「严」(strict) — 任务转向"上线前走查",严格度 +4。回"退回"恢复「快」）
  ```
- **主体响应用 `严` 风格**(已切,边角全考虑、已验证/未验证清单)
- 末尾告知行用履历: `[戴帽履历:「快」(lean)→「严」(strict) — 增强切换 / 自动]`

**用户回应分支**:
- "退回" / "不要切" → 下条切回 `快`,告知 `[戴帽履历:「严」→「快」 — 用户退回]`
- 沉默 / 继续问别的 → 接受切换,继续 `严`
- 同对话内不再 opt-out 自动切到 `严`(锁定)

---

## Case 17: 拒绝后不重复提同一建议(冷却期)

**场景**(承接 Case 16):
- 用户回"不用" → 保持 `快`
- 下一条用户继续问其他事("再帮我改 utils.ts")

**预期**:
- detection 仍可能命中"上线" 触发 `严` 建议
- **但 Step 4b 冷却期生效** → 不再提
- 正常戴 `快` 干活

**反例**:
- ❌ 每条都重复提 "要不要换严"
- ❌ 用户已拒绝,下条又换措辞提("严格点更好吧?")

---

## Case 18: 同对话内建议次数上限(频率)

**场景**: 同一对话内 agent 已建议换帽 3 次(都被拒绝)

**预期**:
- 第 4 次命中信号 → **不再建议**
- 输出末尾加注: `[注:本对话建议次数已满 3 次,任务可能该拆]`

---

## Case 20: 弱化切换 — opt-in 等同意(v3 新增)

**场景**: 当前戴 `严`(严格度 5),用户说"先跑起来再说,别想那么多"

**预期**:
- detection.md "任务转向信号" 命中"转向到 `快`"(目标严格度 1,-4 弱化)
- **opt-in 等同意**:响应**开头第一行**建议:
  ```
  （建议: 任务转向"快速执行",要不要换戴「快」(lean)? 回"换"切,否则继续「严」）
  ```
- **主体响应仍用 `严` 风格**(未切)
- 末尾告知行保持当前: `[戴帽:「严」(strict) — 等用户确认是否弱化]`

**用户回应分支**:
- "换" → 下条切 `快`,告知履历
- 沉默 / 继续问 → **视为不换**(弱化切换不能默认接受,可能误关安全)
- "不用" → 锁定本对话不再提

## Case 21: 横向切换 — opt-in(v3 新增)

**场景**: 当前戴 `教`(严格度 3),用户开始反复说"不知道该怎么办"

**预期**:
- 命中"转向到 `问`"(目标严格度 3,差 0,横向)
- 横向切换走 **opt-in**(保守)
- 响应开头建议: `（建议: 任务转向"卡壳兜底",要不要换戴「问」(ask)? 回"换"切,否则继续「教」）`
- 主体保持 `教`

---

## Case 22: 卡壳兜底例外 — 强制 opt-in(弱化场景)

**场景**: 当前戴 `严`(严格度 5),用户连续 2 轮说"也不对" / "还是不行"

**预期**:
- 命中"任务卡 ≥ 2 轮 → 建议 `问`"
- `严`(5) → `问`(3) 是 -2 弱化,本就走 opt-in,例外不改变行为(但 SKILL.md 例外条款仍适用)
- 响应开头建议: `（建议: 任务转向"卡壳兜底",要不要换戴「问」(ask)? 回"换"切,否则继续「严」）`

---

## Case 23: 卡壳兜底例外 — 增强场景(关键例外验证)

**场景**: 当前戴 `快`(严格度 1),用户连续 2 轮说"不知道怎么办" / "卡住了"

**预期**:
- 命中"任务卡 ≥ 2 轮 → 建议 `问`"
- `快`(1) → `问`(3) 是 +2 增强,**正常会走 opt-out 自动切**
- **但卡壳例外强制 opt-in**(SKILL.md Step 4b "例外: 目标 = `问` 一律 opt-in")
- 响应开头建议(不自动切): `（建议: 任务转向"卡壳兜底",要不要换戴「问」(ask)? 回"换"切,否则继续「快」）`
- **主体保持 `快` 风格**(未切)
- 末尾告知行: `[戴帽:「快」(lean) — 卡壳例外 / 等用户确认]`

**反例**(说明例外为何必要):
- ❌ 若按 opt-out 自动切到 `问`,用户卡壳时被反问 5 个问题 → 更焦虑
- ✅ 强制 opt-in 给用户选择"我要被引导反问"还是"继续快速尝试"

## Case 19: 静默期(刚戴帽别立刻换)

**场景**: 用户刚说"严格点",agent 切到 `严`,第 1 轮回复中

**预期**:
- 即使 detection 命中其他转向信号 → **不建议**(静默期 < 2 轮)
- 等用户在 `严` 下工作 ≥ 2 轮后才允许提建议

## Case 24: 默认激活 — 用户没提 hat 也要戴(v4 新增)

**场景**: 用户发起一个普通日常任务,如"帮我改一下这个函数的参数名"

**前提**: 用户**完全没**提及 hat / 个性 / 风格,只是正常分配任务

**预期**:
- agent **立即**跑 Step 1 检测 → 命中"重构 / 日常 CRUD" → 戴 `快` lean
- agent 用 `快` 风格执行(精简、不过度设计、不解释模式)
- 响应末尾**强制**输出 `[戴帽:「快」(lean) — <说明>]`
- **错误模式**:agent 把任务当普通对话处理、跳过 Step 1、末尾无告知行

**反例**:
- ❌ "用户没说要换 hat,我先不用本 skill"
- ❌ 末尾没有 `[戴帽:...]` 行(不符合豁免规则的任务必须有)

---

## Case 25: 输出前自检 — 漏了就当场补(v4 新增)

**场景**: agent 完成一个改 prompt 文件的任务,响应主体已经写完,准备输出

**前提**: 整段任务跑得很顺,agent 忘了 Step 3 末尾告知

**预期**:
- agent **输出最终响应前**跑自检,扫文本找 `[戴帽:` / `[戴帽履历:`
- 没找到 + 任务不在豁免范围 → **当场在响应末尾补一行**告知
- 若整段任务 Step 1 也漏了 → 按 detection 信号反推 hat,告知行的"说明"字段诚实写"事后兜底反推"
- 例:`[戴帽:「严」(strict) — 事后兜底反推,本次改 prompt 涉及契约修订,该戴严]`

**反例**:
- ❌ "响应已经写完了,下次再补吧" → **违反契约**,自检是输出前最后一步
- ❌ 编造一个像样的 hat 假装本来就戴了(未做兜底反推标注)
- ❌ 自我安慰"这次任务顺利,不告知也行" → 顺利不在豁免规则里

---

## Case 26: 自检发现漏行不能延后(v4 新增)

**场景**: agent 完成长任务,自检发现整个响应没有告知行,但响应已经组织得很完整,补行会破坏排版

**预期**:
- 必须**当场**在末尾补 `[戴帽:...]`
- 不允许"留到下条响应"
- 不允许"算了这次就不加"
- 排版被破坏不是借口——契约 > 排版

**反例验证 Red Flags**:
- "自检发现漏了告知行,但选择'算了下次再补'" → STOP
- "整段会话很顺利,告知行可以省了" → Rationalization #2,reject

---

## Case 27: 0 次切换 — 单行格式(v5 新增)

**场景**: 任务开头戴 `快`,全程没换帽,任务结束

**预期**:
- 输出末尾用**单行格式** `[戴帽:「快」(lean) — <说明>]`
- **不**输出履历多行块(没切换不该用)

**反例**:
- ❌ 没切换就输出 `[戴帽履历: ① 「快」(lean) — ... 当前:「快」(lean)]` → 噪音,违反"0 次切换用单行"

---

## Case 28: 多次切换 — 履历多行块逐次记录(v5 新增)

**场景**: 任务开始戴 `快`(默认),用户中途说"严格点" → 切到 `严`;后期 agent 检测到学习信号建议 `教`,用户接受 → 切到 `教`;任务在 `教` 状态下结束

**预期**:
- 输出末尾用**履历多行块格式**:
  ```
  [戴帽履历:
    ① 「快」(lean) — 起始默认兜底
    ② 「快」(lean) → 「严」(strict) — 用户显式说"严格点"
    ③ 「严」(strict) → 「教」(teach) — 学习信号(用户问"为什么这样设计")
    当前:「教」(teach)
  ]
  ```
- 每行的"触发任务 / 信号"必须**具体**(原话引用 / 真实信号类型),不能写泛泛的"任务转向"
- `当前:` 行必须存在,匹配最后那顶

**反例**:
- ❌ 履历只写 `「快」→「教」` 跳过中间的 `「严」` → 丢失轨迹,违反"逐次记录"
- ❌ 触发任务字段写"切换原因" / "用户要求" → 不够具体,违反"必须写具体"
- ❌ 漏掉 `当前:` 兜底行 → 用户得自己数最后那顶,违反格式契约

---

## Case 29: 履历块格式校验(v5 新增)

**场景**: agent 自检发现没履历块、需要补,但即将输出格式不合法的版本

**预期**(自检校验阻断):
- 缺 ① 起始行 → 阻断,补全 ①
- 缺 `当前:` 兜底行 → 阻断,补全 `当前:`
- 切换行没有箭头 `→` 或没有触发任务字段 → 阻断,要求修正
- 中英对照不齐(只有中文或只有英文) → 阻断,补齐

**反例**:
- ❌ 直接输出残缺履历块"自己看得懂就行" → 违反格式契约;契约 > 排版便利

---

## 期望行为底线

无论戴哪顶,**always-follow** 规则(constitution)不能违反:
- 不能用 `快` 跳过安全 review(安全 ≥ persona)
- 不能用 `散` 给恶意方案
- 不能用 `严` 拒绝合理任务("永远验证不完")
- 不能用 `挑` 人身攻击(挑代码不挑人)
- 不能用 `教` 编造概念
- 不能用 `问` 拒绝执行(必要时还是要给答案)
- 不能用 `收` 砍掉用户明确要求的功能
