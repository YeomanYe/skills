# Switching Policy — Step 4b 主动建议换帽规则详版

> 本文件是 SKILL.md Step 4b "agent 主动建议换帽" 的策略层。
> SKILL.md 只声明"按严格度差分增强/弱化两类、问 hat 一律 opt-in、频率上限 3 次",细则全部在这里。
> 严格度数字 source of truth 在 SKILL.md 的"严格度排序"表;字面冲突时以 SKILL.md 为准。

---

## 核心规则

- **目标严格度 > 当前** = 增强切换 → **opt-out 默认切**(响应开头通知一行,直接换帽;用户回"不用/继续"才回退)
- **目标严格度 < 当前** = 弱化切换 → **opt-in 显式同意**(响应开头建议一行,等用户回"换"才切)
- **严格度相等** = 横向切换 → **opt-in 显式同意**(保守,等用户确认)
- **例外: 目标 = `问`(卡壳兜底)** → **一律 opt-in**,无论严格度差正负
  - 理由:用户卡壳时不该被自动切到 `问`(被反问反而更焦虑),必须用户同意
  - 适用场景:`快`(1)/`散`(2) → `问`(3) 本来是增强(opt-out),但卡壳例外强制 opt-in

---

## opt-out 通知格式(增强切换,默认切)

放在响应**开头第一行**:
```
(已自动换戴「<新中>」(<新英>) — 任务转向 X,严格度 +N。回"退回"恢复「<原中>」)
```

主体响应**用新 hat 风格**(已切),末尾告知行用履历格式。

---

## opt-in 建议格式(弱化或横向,等用户)

放在响应**开头第一行**:
```
(建议: 任务转向 X,要不要换戴「<新中>」(<新英>)? 回"换"切,否则继续「<当前中>」)
```

主体响应**保持当前 hat 风格**(未切),末尾告知行保持当前 hat。

---

## 触发条件(任一命中)

- 当前 hat = `快`,但新输入含强信号属于其他 hat(如"上线前" → 建议 `严`)
- 当前 hat = `散`,但用户开始说"挑最关键的" / "决定了" → 建议 `收`
- 当前 hat = `严`,但用户开始说"先跑起来再说" → 建议 `快`
- 当前 hat = `教`,但用户开始独立做出选择 → 建议脱帽到 `快`
- 任务卡住 ≥ 2 轮没进展 → 建议 `问`(让用户澄清)

完整转向信号清单见 `detection.md` "任务转向信号" 段。

---

## 不要触发(避免烦扰)

- 用户已经在当前帽下连续工作 < 2 轮(**静默期**)
- 用户刚刚显式拒绝过换帽建议(**冷却期**:同一对话内不再提相同建议)
- 当前 hat 跟建议 hat 行为差异不大(如 `快` → `挑` 在简单 review 场景)
- **同对话内 4b 触发总次数已达 3 次**(**频率上限**:opt-in 建议 + opt-out 自动切**合并计数**,超出不再触发,改输出注脚 `[注:本对话建议次数已满 3 次,任务可能该拆]`,详见 output-contract.md "频率上限注脚" 段)
- **建议的目标 hat 会削弱当前任务的 constitution 要求**(安全审 / 验证类任务不能建议切到 `散`/`快` 等会弱化严格度的帽)

---

## 用户回应处理

### opt-in 场景(弱化/横向)

- "换" / "好" / "yes" → 切到建议 hat,下条末尾告知履历
- "不用" / "继续" / "no" → 保持当前 hat,本对话不再提同一建议
- 沉默或继续任务 → 视为"不换"

### opt-out 场景(增强)

- "退回" / "不要切" / "回去" → 立即切回原 hat,下条末尾告知履历"已退回"
- 任何其他回应(包括沉默) → 接受换帽,继续用新 hat
- 锁定: 本对话内同一退回路径不再自动 opt-out 切换(避免反复切回又切走)

---

## 优先级:4a vs 4b

同一轮同时触发时,**4a(用户打断)永远优先于 4b(agent 建议)** — 先执行 4a 切帽,4b 建议作废(不输出建议行)。
