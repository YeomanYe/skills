# Output Contract — 末尾告知行格式 + 自检

> 本文件是 SKILL.md 输出契约的详版。SKILL.md 只声明"必须输出告知行 + 自检是最后一步",细则全部在这里。

---

## 两种格式按"同一任务内切换次数"分

### 0 次切换 — 单行格式

```
[戴帽:「<中文>」(<英文>) — <一句话说明>]
```

适用于全程戴一顶帽的任务。

### ≥ 1 次切换 — 履历多行块格式

```
[戴帽履历:
  ① 「<中文 1>」(<英文 1>) — <起始原因 / 默认兜底>
  ② 「<中文 1>」(<英文 1>) → 「<中文 2>」(<英文 2>) — <触发任务 / 信号>
  ③ 「<中文 2>」(<英文 2>) → 「<中文 3>」(<英文 3>) — <触发任务 / 信号>
  当前:「<最后那顶中>」(<最后那顶英>)
]
```

**格式要点(逐条必守)**:

- 编号从 ① 开始,**每次切换占一行**
- 第 ① 行是起始状态,只写一顶帽 + "起始原因 / 默认兜底"
- 第 ② 行起每行格式 `「旧」→「新」 — <触发任务 / 信号>`
- "触发任务 / 信号" 必须**写具体**(`改 prompt 契约` / `用户问"为什么这样设计"` / `跑 lint+test`),**不能写**泛泛的 "切换原因" / "任务转向"
- 最末 `当前:` 行兜底,让用户一眼看到此刻戴的是哪顶
- 整块包在一对 `[戴帽履历:` ... `]` 里
- **不设硬性长度上限**;但 Red Flags 有 "同一任务戴 ≥ 3 顶 = 任务该拆" 的软约束,触发 ≥ 3 顶时考虑拆任务

**示例**:

```
[戴帽履历:
  ① 「快」(lean) — 起始默认兜底,日常 prompt 微调
  ② 「快」(lean) → 「严」(strict) — 改 hat Output Contract(契约修订,进严格模式)
  ③ 「严」(strict) → 「教」(teach) — 用户问"为什么不设长度上限"(学习信号)
  当前:「教」(teach)
]
```

### 何时输出哪种

| 同一任务内的切换次数 | 输出格式 |
|---|---|
| 0 | 单行 `[戴帽:...]` |
| ≥ 1 | 履历多行块 |

判定时机:响应生成的最后一步(在"末尾告知行自检"之前已经选定格式)。

## 末尾告知行自检(必跑,放在响应生成的最后一步)

**输出最终响应前**,agent 必须做一次自检:

1. **扫**最终响应文本,找 `[戴帽:` 或 `[戴帽履历:` 开头的行
2. **没找到** 且 当前任务**不在豁免规则覆盖范围**:
   - 同一任务内**未发生切换**(0 次) → **立即补一行** `[戴帽:「<当前 hat 中>」(<当前 hat 英>) — <一句话说明>]`
   - 同一任务内**已发生 ≥ 1 次切换** → **立即补一个履历多行块**(按"≥ 1 次切换 — 履历多行块格式"段),逐次列出每一步切换的触发任务 / 信号
3. **没找到** 但任务**在豁免规则覆盖范围**(如纯命令 / 短回复 / 用户明确禁用) → 跳过,不补
4. **找到了** → 校验格式合法:
   - 单行格式:中英对照齐全 / 说明非空
   - 履历多行块:有 ① 起始 + 各次切换行(箭头 + 触发任务)+ `当前:` 兜底行

### 反推当前 hat 的兜底

如果自检时发现整个任务没经过 Step 1 选帽(漏掉了),按以下顺序兜底反推:

- 任务有明显 MVP / 测试 / review / 风格 / 学习 / 卡壳 / brainstorm 信号 → 按 detection 表反推该戴的帽
- 都没匹配上 → `快` lean(默认兜底)

兜底反推后告知行的"说明"段要诚实写"事后兜底反推",例:

```
[戴帽:「快」(lean) — 事后兜底反推,本次任务无强类型信号,按默认 lean 处理]
```

## 反例

| 错误模式 | 正确做法 |
|---|---|
| 响应输出后才想起没加告知行 → 算了下次再补 | **不允许**。自检是输出前的最后一步,漏了就在末尾补,绝不"留到下次" |
| 自检发现漏了 → 编一个像样的 hat 写上去糊弄 | **不允许**。要么诚实写"事后兜底反推",要么如果真的整段没用 hat 风格,就承认"未戴帽" 并下次任务开头补做 Step 1 |
| 把豁免规则扩大化("这条不算" / "用户没要求") | **不允许**。豁免严格按下文 "豁免规则" 段执行,不自行扩展 |

## 频率上限注脚(Step 4b 触发但被压制时)

当 4b 命中触发条件但被"频率上限"压制(已建议 ≥ 3 次),响应末尾的告知行**额外加一行注脚**:

```
[戴帽:「<当前中>」(<当前英>) — <说明>]
[注:本对话建议次数已满 3 次,任务可能该拆]
```

注脚只在频率上限触发时输出,冷却期 / 静默期压制不需要注脚(那是正常节奏控制)。

## 豁免规则(不输出告知行)

以下场景**跳过告知行**(避免污染极简响应):

- 用户消息 < 5 字("好" / "谢谢" / "ok" / "继续")
- 纯执行命令且无决策成分("跑下测试" / "git status" / "ls")
- 用户已显式说"别加那行" / "不要 [戴帽] 标记"
- 当前对话已连续 ≥ 3 条没切换 hat(避免重复告知)

豁免不等于"不戴 hat"——hat 仍激活并影响输出风格,只是不显示告知行。
